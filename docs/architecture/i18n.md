# 国际化（i18n）架构

最后更新：2026-09-09

状态：PLANNED

本文定义 CloudPath 的国际化边界、运行模型和插件本地化契约。用户侧名称仍以
[name-lexicon.md](name-lexicon.md) 为领域词表；i18n 负责语言资源、格式化和回退，不改变协议字段、机器 ID、
数据库列或 API 路由。

## 目标

- WebUI 支持 `zh-CN`（默认）与 `en-US`，语言选择可持久化。
- 所有静态 UI 文案通过统一 `t()` 访问，禁止新增未登记的硬编码 CJK 文案。
- 后端不返回面向用户的本地化长文本；返回稳定 `code`、`params` 和 `request_id`，由客户端翻译。
- Driver / Application / Connector 的标题、描述和插件 UI 导航/页面标题支持可选 locale map，并保持旧字段兼容。
- 日期、数字、单位使用 `Intl` 按当前 locale 格式化；用户数据、设备名、raw JSON、日志和机器 ID 永不翻译。

## 非目标

- 不在本次改造中翻译全部项目文档、GitHub README 或运维日志。
- 不引入翻译管理平台、机器翻译服务或运行时远程加载语言包。
- 不为单个插件创建业务专用翻译表；插件通过公开契约提供自己的展示文本。
- 不改写已有协议字段、数据库列、路由和稳定 ID。

## Locale 模型

```text
supported: zh-CN, en-US
default:   zh-CN
fallback:  zh-CN
```

选择顺序：

```text
localStorage 中的用户选择
→ navigator.languages / navigator.language
→ zh-CN
```

`zh`、`zh-Hans` 归一化为 `zh-CN`；`en`、`en-GB` 等归一化为 `en-US`。未知 locale 不回显为可选项。

## WebUI 运行时

使用：

- `i18next`
- `react-i18next`
- `i18next-browser-languagedetector`

资源按 `locale / namespace` 组织，v1 使用静态资源，保证首屏确定性和测试稳定：

```text
webui/src/i18n/
  config.ts                 locale 归一化、存储、支持列表
  index.ts                  i18next 初始化
  resources.ts              locale + namespace 聚合
  format.ts                 locale-aware 时间、数字、相对时间
  pluginText.ts             插件声明文本的 locale 解析
  locales/
    zh-CN/*.ts
    en-US/*.ts
```

固定 namespace：

```text
common nav auth overview devices edges activity plugins settings admin errors plugin
```

组件只使用语义 key，例如：

```tsx
const { t } = useTranslation('devices')
t('detail.tabs.actions')
t('status.online')
t('error.offline', { name: deviceName })
```

禁止把中文原文当 key，禁止在组件内维护第二套业务词典。插件声明的展示名、用户输入和动态数据不进入静态资源。

## 插件本地化契约

现有 `title` / `name` / `description` 字段保留为默认值。新增可选 `i18n` map：

```json
{
  "title": "温度",
  "i18n": {
    "zh-CN": "温度",
    "en-US": "Temperature"
  }
}
```

覆盖对象：

- Plugin Manifest 的 `contributes.*[].title`
- Device Descriptor 的 `entities[].name`
- Capability Metadata 的 `title`
- Capability Action 的 `title` / `description`
- Capability Event 的展示标题（如果声明存在）
- Plugin UI 的 `ui.navigation.title` / `ui.pages[].title`

解析顺序：

```text
精确 locale
→ 语言基础 locale（zh / en）
→ i18n map 中的 zh-CN / en-US 兼容值
→ 旧 title / name / description
→ 平台通用词典
→ humanize(machine name)
```

机器 ID、Capability URI、事件类型、property key 永远不翻译。

## 用户可见文案原则

所有用户可见文案必须面向普通用户，直接说明“发生了什么”和“下一步怎么做”。不要把契约、实体、运行时、fail-closed、revision、namespace、descriptor、capability、machine ID 等工程术语带进主界面；这类细节只放在高级详情、日志或开发者文档。

- 标题：用一句话说明当前状态或问题。
- 说明/提示：说明影响，并给出一个可执行的下一步；没有可执行动作时明确“稍后重试”或“联系管理员”。
- 错误：优先展示稳定 code 对应的本地化文案，不直接展示后端 `message`、原始 JSON 或堆栈。
- 数据：设备名、用户名、日志、secret handle 等用户数据原样保留，不伪装成翻译。

## 后端错误契约

后端只负责稳定语义，不负责语言：

```json
{
  "error": "device_offline",
  "code": "device_offline",
  "message": "device offline",
  "request_id": "req_...",
  "params": {"device_id": "..."}
}
```

约束：

- 新错误必须注册稳定 code。
- `message` 只用于日志、诊断和旧客户端兼容，不作为新 UI 的翻译源。
- 前端 `errors` namespace 按 code 翻译；未知 code 回退到 HTTP 状态通用文案。
- 插件写路径的 `PluginErr*` 和现有 `apiErr*` 是首批 canonical code。

## 格式与数据

- 时间：`Intl.DateTimeFormat(locale, ...)`
- 数字：`Intl.NumberFormat(locale, ...)`
- 相对时间：由 i18n 资源 + 统一格式化函数生成，不再硬编码“分钟前”
- 单位：机器单位保持 canonical；显示单位通过 `unitLabel()` 和 locale 资源转换
- 枚举：平台枚举使用资源；插件业务枚举保留插件声明或原值，不猜语义
- raw JSON、日志、设备名、用户名、secret handle 原样展示

## 质量门禁

- `i18n` 资源 key 必须成对存在；缺失 key 由测试失败。
- 增加伪 locale 或 key 回显测试，防止“看起来翻译了但仍是中文”。
- `scripts/check_i18n.py` 扫描源码中未登记的 CJK 字面量；测试文件、注释和允许的动态数据白名单需显式登记。
- 语言切换后关键页面不刷新丢失状态，时间/数字格式随之变化。
- 插件 `i18n` 缺失时保持旧行为；存在时按 locale 选择。

## 实施阶段

1. 前端 i18n runtime、locale 持久化、公共格式函数和语言切换入口。
2. 按 domain 迁移静态 UI 文案：auth、overview/devices、edges/activity、plugins、settings/admin。
3. 后端稳定错误码和 `params` 兼容层。
4. Plugin Manifest / Descriptor / Capability schema、Go SDK、TS 类型和插件文本解析。
5. 参考插件适配、CI 门禁、伪 locale、E2E 和文档收口。

## 验收

- 切换 `zh-CN` / `en-US` 后，导航、列表、详情、表单、错误态、插件生命周期文案和插件 UI 导航/页面标题全部切换。
- 新增插件可以只声明 `title`，也可以声明 `i18n`；两种都能工作。
- 后端错误不再依赖 message 文本驱动 UI。
- 现有测试通过；新增 i18n 门禁和关键页面 E2E 通过。
